Overview

What you get, what to run, and what holds. Then pick a path.

Put a price on any HTTP app and get paid per request, in USDC, with no protocol fee and no change to your app. A TOON node is a paid reverse proxy: it sits in front of your app, refuses an unpaid request with the price, and hands your app a plain HTTP request once it has been paid for. toon installs in one line and runs the node for you.

Three steps

1. Install. Linux, x86_64 or aarch64, glibc 2.35 or later; docker and systemd --user on the machine. No Rust toolchain from a release.

The shell
curl -fsSL https://raw.githubusercontent.com/toon-protocol/toon_cli/main/install.sh | sh

2. Create and fund your agent node on the devnet, the test network. init needs a passphrase file first; Your first agent node shows that.

Devnet, free
toon init --accept-anyone-terms     # a wallet, and a relay reachable as a hidden service
toon wallet fund                    # test tokens from the faucet

3. Start it and see it answer.

The shell
toon up                             # a systemd --user unit, so it outlives this terminal
toon status                         # what is running, and at which address

What holds

  • You set the price and keep it. A whole number of the token's smallest unit per route; 1000 is 0.001 USDC. There is no protocol fee.
  • A request costs a signature, not a transaction. The caller deposits once into an x402 channel on Base or Solana; one onchain transaction every ten minutes lands everything since the last.
  • Your app never sees a payment. It gets a plain HTTP request and three optional headers saying who paid, how much, on what chain.
  • One binary, MIT. toon runs the node as a hidden service with no domain and no open port; every command that pays states its amount and needs --yes.

Below: the paths, the wire, and where everything lives.

Pick your path

  • I have an app to charge for Three commands give you a node; one toon add puts your app behind it with a price. Prefer to write every file yourself? The connector, by hand.
  • I want to pay for requests Install the client, make a wallet, open one channel, and buy a request. The first one is on devnet and costs nothing.
  • I want no domain, no certificate, no open port A new agent node is a hidden service at a .anyone address by default. Hidden services is the same thing done by hand.
  • I want an agent to run it spaceturtle runs a node from your own machine as a hidden service, with the agent kept away from the money.
  • I run a node and want traffic Join a network, peer with another operator, set routes and prices, and carry packets one hop further for a fee.

What a paid request looks like

An unpaid request is refused with the price, as an x402 v2 document a stock client can read.

On the wirex402 v2
# an unpaid request to a priced route
POST /ilp                  no voucher attached
402 Payment Required
{ "x402Version": 2,
  "accepts": [{ "scheme":  "batch-settlement",
               "network": "eip155:8453",
               "amount":  "1000",
               "payTo":   "0x…" }] }

# the same request, with a signed voucher
POST /ilp                  voucher: 1,000 units
200                        your app's answer, sealed

The caller then attaches a signed voucher to every request: a running total the node accepts only if it rises by the price. Underneath, the node is an Interledger connector, which is why its one endpoint is /ilp; Concepts defines every word used here.

Where things live

RepositoryWhat it is
connectorThe node: one Rust binary, one TOML file. Its docs/ hold the specs, the ADRs and the wire vectors that every other repository replays.
toon-client@toon-protocol/client, the payer, as a library and as the toon-client CLI.
toon_clitoon, the program that runs and manages an agent node: wallet, apps, peers, routes, prices, channels and the relay.
spaceturtleThe agent and the harness that run an agent node from your own machine.
relay, store, gas-station, anytoonApps that run behind a node today, each a worked example of the app side. The ecosystem page lists them all.

These pages are written from those repositories' own guides. Where a page here and the repository disagree, the repository is right, and each page says which file it was written from.
