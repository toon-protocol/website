# website

The source of [toon.ar.io](https://toon.ar.io): the TOON Protocol landing page, the docs
and the apps and agents pages.

```
index.html              the landing page: hand-written; build.py copies the stylesheet into it
docs/*.html             built from src/docs/*.html by build.py
apps/index.html         built from src/apps.html: every app, in the shape of a marketplace
agents/index.html       built from src/agents.html: every agent that speaks TOON
install.sh              the installer at https://toon.ar.io/install.sh: a stub that hands over to toon_cli's
assets/site.css         the one stylesheet, shared by every page
assets/search.js        the docs search box; docs/search/<slug>.js is its index, one file per page, built by build.py
assets/docs.js          the docs pages' phone menu, theme picker, "On this page" highlight and copy buttons
assets/fonts/           self-hosted latin subsets of IBM Plex Sans Condensed, Plex Sans and Plex Mono, with their OFL licences
assets/icon/            the brand's mark as SVG: full, two-bar and 16px, light and dark
build.py                the only build step; standard library only
check.py                the site check over the built pages, run by the CI gate; standard library only
manifest.template.json  the Arweave path manifest, regenerated by build.py from the files git tracks
src/                    the page fragments you edit
.brand/                 the brand's messaging, voice and identity text, copied verbatim from toon-protocol/brand
.publish/               the CI publish through TOON: run by .github/workflows/publish.yml (see Publishing)
```

The docs follow the layout of [herdr.dev/docs](https://herdr.dev/docs/): a full-width header
with the search in its middle, the sidebar flush left, "On this page" flush right, and a
splash for the docs home.

The site carries three scripts: the copy button on the landing page, the docs search
(`assets/search.js`), which reads `docs/search/<slug>.js`, an index file per page that `build.py` writes from
`src/docs/` with one record per page section, and `assets/docs.js`, the docs pages' phone
menu, theme picker, "On this page" highlight and copy buttons. Without scripts the search
box and theme picker stay hidden and the sidebar sits above the page on a phone. The site is stored on Arweave and reached through the ArNS name
`toon`. Each revision of the landing page is bought as a paid TOON write through the live
node, and the docs page "Proof" (`src/docs/proof.html`) embeds the receipts of the revisions
before it.

## Editing

- **The landing page** is `index.html`. Edit its markup directly, except the header and
  the footer, which `build.py` writes between the `<!-- header -->` and `<!-- footer -->`
  markers from the same templates every other page uses. Its `<style>` block is a
  copy of `assets/site.css` that `build.py` refreshes on every build, so the one file stands
  alone, as every earlier revision did, while the stylesheet has a single source. Edit
  `assets/site.css`, never the copy.
- **The look** follows the brand's identity brief (`.brand/identity.md`). Palette: Paper
  background, Ink text, one Gold (a fill only), Gold text for prices and links on Paper, Wire for
  lines, and Night for terminal panels and the docs' dark scheme. The retired accent `#d9b65c`,
  purple, teal, blue links and gradients stay out. Type: Plex Sans Condensed (Bold display,
  SemiBold h2), Plex Sans (Regular body at 17px, SemiBold h3) and Plex Mono (Regular and Medium
  for code, commands, prices and labels), all served from `assets/fonts/`. Labels and live/next
  tags are the only uppercase text. The landing, apps and agents pages are always Paper, with
  Night terminals; only the docs follow `prefers-color-scheme` and the theme picker. Colours are
  tokens at the top of `assets/site.css`; change a token and run `python3 check.py`, which
  holds the text pairings that must reach 4.5:1 (see "What the gate checks").
- **A docs page** is a body fragment in `src/docs/<slug>.html`. The title, summary, section
  and order come from `NAV` in `build.py`. Every `<h2>` gets an anchor and an entry in the
  page's table of contents. End each page with a `<p class="source">` naming the
  repository file it was written from, so the next editor can check it against the source.
- **The apps and agents pages** are `src/apps.html` and `src/agents.html`. A new app or
  agent is one `<li>` in the grid and a bump of the count in the page header. Each card's
  stars, language and version are typed by hand from `gh api repos/<owner>/<name>`; reread
  them before a publish.
- Then run the build:

  ```sh
  python3 build.py
  ```

Preview with any static server, for example `python3 -m http.server 8765`, then open
`http://127.0.0.1:8765/`.

## Before publishing

1. **Prices.** The "Priced live" cards on the apps page are a snapshot read off the live
   agent node's `GET /ilp`. Reread it, then update the read date and the network on every
   price (the apps page cards and trust line, and the agents page's hermes-toon card) if a
   price or the network changed, and the route on each card to the prefix that node serves.
   Each price carries its unit or token, its read date and the network it was read on, and
   that network is the one the status chip (`STATUS_LIVE` in `build.py`) calls live.
2. **Release tags.** The version named in `src/docs/install.html` is toon_cli's latest
   release (`gh release list -R toon-protocol/toon_cli`); the Docker tag in
   `src/docs/run-a-node.html` is the connector's (`gh release list -R toon-protocol/connector`).
3. **Docs drift.** Each docs page names the repository file it was written from. Diff that
   file against the last time the page was touched.
4. **Receipts.** Add the landing-page revision being replaced to the list in
   `src/docs/proof.html` and to the JSON in its `<details>` block: its Arweave transaction id (the `x-arns-resolved-id`
   header of `curl -sI https://toon.ar.io`), `sha256sum` of the file as served, byte size,
   the claim on each hop, and the block date. A page cannot contain its own hash, so this
   is always done for the previous revision, never the current one.
5. **External links.** Check them with curl. npmjs.com, basescan and the Solana explorer
   block curl and must be checked in a browser.

   ```sh
   python3 build.py
   grep -ho 'href="https\?://[^"]*"' index.html docs/*.html apps/*.html agents/*.html | sed 's/href="//;s/"$//' | sort -u \
     | while read u; do printf '%s %s\n' "$(curl -s -o /dev/null -w '%{http_code}' -L "$u")" "$u"; done | grep -v '^200'
   ```
6. **Copy.** Read for what the check cannot catch: the tone rules in `.brand/voice.md`,
   claims that need proof (`.brand/messaging.md` marks which are owed), a "paid" page carrying
   the live/devnet label, whether the route diagram reads well, and whether the terminal
   output still matches what the named `toon` release prints. The header carries "Run a node"
   and the footer states "No protocol fee"; the check enforces neither. The typing tape in the operators
   section is a CSS animation over real commands in workflow order; reduced motion holds its
   first line.
7. **The status chip.** Every header carries one chip saying what is live and what is next,
   built from `STATUS_LIVE`, `STATUS_NEXT` and `OPERATORS` in `build.py`. When the network
   changes, change them there and rebuild. `OPERATORS` is the number of independent connector
   operators and renders only above zero.
8. **How the pages look.** Open each page at phone width and at desktop width: no sideways
   scroll, terminals wrap or scroll inside their own panel. With the system theme dark, the
   landing, apps and agents pages stay Paper, the docs turn Night, and the mark shows in both.
   Check the favicon in a light and a dark browser.
9. **The home-router demo.** `DEMO` in `build.py` holds the demo's excerpt lines (copied verbatim
   from the recording), its devnet label and its links. Empty, the landing page shows nothing in
   its place and `check.py` fails. A later run, or a mainnet run, changes only `DEMO`. Wherever the
   hero says "no open port" it links the demo and does not imply mainnet.

## What the gate checks

`python3 check.py` reads the built site, never the sources, and prints one line per violation
naming the page, the rule and the offending text. The CI gate runs it after the build, so the
factory's agents and every human PR meet the same bar. Its rules hold their lists as plain
data in `check.py`, each naming the `.brand/` file it was copied from; when the brand package
changes a list, update it there by hand.

- **Copy.** The landing h1 is "Your machine. Paid per request." and the supporting statement is
  present. The retired taglines, the "never say" phrases and "Get paid." as a sentence of its
  own appear on no page (title and meta tags included) except the proof page's receipts.
  "hidden service" stays out of every heading (h1 to h6) on the landing, apps and agents pages
  and out of the landing title and social titles (the docs may use it in headings); "open port"
  is allowed there. The landing page must carry the `.demo-proof` block: it links the demo README and
  the settlement transaction, and says "devnet". "onion" stays off the marketing pages, which have no exclamation mark outside code.
  The docs sidebar has no banned phrase.
- **Social tags.** `head()` in `build.py` writes the card's Open Graph and Twitter tags, plus `og:url`, on every built
  page. Every page but the landing page must carry `og:title` equal to its `<title>`, `og:description`, `twitter:card`,
  and the card as `og:image` and `twitter:image`, an absolute `toon.ar.io` URL of a file in the repo.
- **Chrome.** Every page links the 16px favicon as files, the light one by default and the dark
  one for a dark scheme. Its header mark is the two-bar mark with no wire and no colours of its
  own, so the page's theme sets its light and dark variant. It has exactly one status chip that
  says "Live" and "Next".
- **Type, colour and hosts.** The stylesheet declares only the three Plex families, its type
  stacks lead with one, and every font file it names exists. Archivo, JetBrains Mono and the
  retired accent `#d9b65c` appear nowhere in the stylesheet, the landing page's inlined copy or
  the manifest. Each text pairing in `PAIRINGS` reaches 4.5:1 in the light set and in both dark
  sets (the theme picker's and the docs' system theme). No tag on any page, and no `url()` in the
  landing page's inlined stylesheet, loads a stylesheet, font, script or image from another
  host. The landing page has one script; the apps and agents pages have none.
- **Links and manifest.** Every internal `href` and `src` resolves to a file, and every
  same-site `#fragment` to an id on its page. The manifest lists every page and referenced
  asset, only files that exist, and nothing under `src/`, `__pycache__/` or a dot-directory.

## The install URL

Every install command on the site reads `curl -fsSL https://toon.ar.io/install.sh | sh`.
That path is served by the site itself, from `install.sh` in the manifest, so it only works
once a revision that carries the file is live on Arweave. Until then the gateway answers
the path with the landing page, and piping that into `sh` fails. Check before and after a
publish: `curl -fsSL https://toon.ar.io/install.sh | head -1` must print `#!/bin/sh`.

## Publishing

The site is published by hand from GitHub: **Actions → publish → Run workflow** on `main`. The
workflow (`.github/workflows/publish.yml`) runs the gate first, then `.publish/publish.mjs` in the
mode you pick:

- **plan** spends nothing. It prints the CI wallet's two addresses, the connector's live terms,
  the files that changed since the live publish and what uploading them would cost.
- **upload** writes each changed file to Arweave through the mainnet store
  (`g.toon.store`, kind 5094), paid per request plus per KiB on the CI wallet's channel to the
  connector at `https://proxy.store.toonprotocol.dev`. It then uploads a `publish-index.json`
  (each path's sha256 and transaction id) and the filled path manifest, and prints the manifest's
  id and a preview URL. `toon` is not changed.
- **publish** uploads the same way, then points the ArNS name `toon` at the manifest. The CI key,
  a controller of `toon`, signs the record update, and the gas station (`g.toon.gas`, kind 5096)
  pays its Solana fee and broadcasts it. The workflow then waits until `toon.ar.io` resolves to
  the new manifest (a gateway may keep the old one for the record's TTL, 900 s) and checks that
  `install.sh` is served.

Only files whose sha256 differs from the live `publish-index.json` are uploaded again; the rest
keep their transaction ids. The manifest lists only files git tracks, so `git add` a new file
before you build, and an untracked draft stays out. It serves `index.html` at the root and every
other path beneath it, so `toon.ar.io/docs/run-a-node.html` resolves.

**The wallet** is one repository secret, `WALLET`: the solana-keygen keypair (an array of 64
numbers) of `AXobAqdzsxhhEb85aduWBChkSrEjGmswJjozXHKfRKDj`. The Base key that pays the channel is
derived from it, and `.publish/config.json` pins both addresses; the run stops if they differ.
Why, and what changing it costs, is [ADR 0001](.agents/adr/0001-one-ci-secret-and-a-derived-base-key.md).

**The channel** is opened once, on a maintainer's machine, never by CI. A run that has no channel,
or too little left in it for the plan's estimate, stops before it pays:

```sh
npm ci --prefix .publish --ignore-scripts
WALLET_FILE=~/.config/solana/toon-ci.json node .publish/publish.mjs plan
WALLET_FILE=~/.config/solana/toon-ci.json node .publish/publish.mjs upload --open-channel
git add .publish/channel/channels.peers.json   # the channel's binding: no secret in it
```

`--open-channel` opens the channel (or tops it up) with `deposit` from `config.json`, paying its
own gas in ETH on Base. The committed binding is what lets CI find the channel again; the
watermark beside it is rebuilt each run from the chain and the connector's `claim-state`.

Revisions 1 to 8 of the landing page were bought the same way by hand, as paid TOON writes through
the store app behind a live node; the first paid writes are documented at
[boughtviatoonnode.ar.io](https://boughtviatoonnode.ar.io/).
