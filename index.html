Pay-per-request for agents, APIs and apps

Value, routed.

Put a price on any HTTP endpoint. Get paid per request, settled onchain, without changing your app. The caller pays with a signed voucher, an IOU against a deposit it locked on chain once. Your app sees a plain HTTP request.

How it works

A paid reverse proxy. It terminates payment the way nginx terminates TLS.

A TOON node sits in front of your HTTP app. You set a price per route. Every request that reaches your app has already been paid for.

  • 1

    The refusal names the price

    An unpaid request gets an x402 402 Payment Required with the exact amount, token, chain and address. A caller never guesses.
  • 2

    The caller pays with a voucher

    The caller opens an x402 payment channel once, then attaches a signed voucher to every request. No account, no card, no signup, no API key.
  • 3

    The app gets plain HTTP

    The node checks the voucher, unseals the request and forwards it. Your app does not change. No SDK, no invoices, no payment code.

It is built for machines that transact thousands of times a day: agents paying for inference, storage and relays; services metering each other; apps that want to charge per call without building billing. It is not a consumer checkout, and does not try to be.

For operators

Run a node in three steps

One binary, one config file, one command. There is no account to open, nobody to ask, and nothing to add to your app.

  1. Pull it

    The connector ships as one Docker image. Pull it and generate the node's key with one line of openssl.

  2. Price a route

    Four lines of TOML point a price at your app. A settlement block names the token you want to be paid in; the guide has the addresses to copy.

  3. Start it

    docker compose up -d. Your node answers GET /ilp with its price list and starts collecting.

The shellconnector 2026.09.29.1
docker pull ghcr.io/toon-protocol/connector:rust-2026.09.29.1

docker compose up -d
connector.tomlone route
[[routes]]
prefix      = "g.example.app"
handler_url = "http://app:3100/"
price       = 1000      # 0.001 USDC per request

Before it faces the world, put a TLS proxy in front of it: a TOON node refuses plaintext peers. The operator guide covers that, the settlement block, and peering with a second node.

For callers

Paying is one install

The client asks a node what it charges, opens the channel once, and does the sealing and the vouchers on every request after that. A refusal comes back as a value, not an exception.

  • No account anywhere

    A wallet and a deposit are the whole onboarding. The node never learns who you are.

  • One channel, many apps

    Routes chain across nodes. Fund one channel and reach apps behind other operators' nodes through it.

  • Works from any language

    The wire is x402 v2 over HTTP. The TypeScript client is the reference; the client-edge spec is the contract.
TypeScriptnpm install @toon-protocol/client
import { ToonClient } from '@toon-protocol/client';

const client = await ToonClient.create({
  connector: 'https://proxy.ario.devnet.toonprotocol.dev',
  mnemonic: process.env.TOON_MNEMONIC,
  channelStore: `${process.env.HOME}/.toon/channels.json`,
});

await client.channel.open({ deposit: 100_000n }); // 0.10 USDC

const answer = await client.send({ body: 'hello' });
if (answer.fulfilled) {
  console.log(answer.status, answer.text());  // the app's own response
  console.log(answer.claim.amount);           // 1000n (0.001 USDC)
} else {
  console.log(answer.code, answer.message);   // a refusal, not an exception
}

await client.close();

What it costs

You set the price. You keep the price.

A route charges a flat amount per request, plus an optional rate per KiB for large bodies, in the token you settle in. Prices count the token's smallest unit, the way a card terminal counts cents: in USDC, 1,000 units is a tenth of a cent.

There is no protocol fee and no percentage cut. Vouchers are redeemed onchain in batches, on the channel contracts the x402 ecosystem already runs, so one transaction settles thousands of requests. The cost of a request is the price you set, not a gas fee.

The software is MIT licensed. There is no plan, no tier, no minimum and no payout schedule. Nobody sits between the caller's channel and your key.

Why it is better

Sending a message and sending money are the same action.

  • Against paying onchain per call

    A TOON request costs a signature, not a transaction. No gas per request, no block to wait for, and a tenth of a cent is a real price, not a rounding error.

  • Against API keys and invoices

    Nothing to provision and nothing to chase. The caller pays with the request, and an unpaid request is refused before it reaches your app.

  • Against metered billing services

    No percentage cut, no minimums, no payout schedule. Vouchers settle to a key you hold, in the token and on the chain you chose.

  • Against a plain reverse proxy

    Routes chain. A node can forward to another node's paid route and keep a fee, so one caller reaches apps behind other nodes through one channel. Forwarding hops carry the payload sealed and cannot read it.

Only TOON

Fund one channel, reach many apps.

Routes chain across nodes with the payload sealed. Each hop keeps its own fee, a hop can convert between tokens at a rate it declares, and a node can run as a hidden service at a .anyone address on the Anyone network, with no domain and no open port. The app never sees a payment, and an intermediate hop never sees the request.

Pay-per-request protocols answer "what does this cost, and is it paid?" TOON settles on them and adds the one thing they do not have: a route.

Where it sits

Two kinds of agent payment protocol. TOON is the first kind, with a route.

ProtocolsWhat they answerAnd TOON
Pay per requestx402, L402, Circle Nanopayments "What does this request cost, and is it paid?" A 402 names a price; the caller pays onchain, over Lightning, or through a batching service. ILP routes, x402 settles. Every TOON channel is an x402 batch-settlement channel, and an unpaid request gets an x402 document. What TOON adds is the path: ILP carries the voucher from node to node, so a caller is not limited to the seller it opened a channel with.
Authorize a purchaseGoogle AP2, Stripe and OpenAI ACP, Visa Trusted Agent Protocol, Mastercard Agent Pay "Did a human authorize this cart?" Mandates, checkout sessions and agent credentials on card rails, with refunds and disputes. A different question. TOON answers "was this packet paid for before the app saw it?" No cart, no card, no chargeback.
Only TOONa route, not just a price Fund one channel, reach many apps. Routes chain across nodes with the payload sealed, each hop keeps its own fee, a hop can convert between tokens at a rate it declares, and a node can run as a hidden service at a .anyone address. The app never sees a payment.

FAQ

Questions operators and callers ask

Is TOON an x402 facilitator?

No. A facilitator verifies and settles payments for a seller as a hosted service, usually for a fee per settlement. A TOON node is software you run: it verifies vouchers itself, offchain, and settles its own channels in batches. Every TOON channel is an x402 batch-settlement channel, so the contracts and the 402 document are x402's; the node is yours. There is no fee to anyone but you.

Do I have to change my app?

No. Your app is an ordinary HTTP service behind a route's handler_url. It receives an ordinary HTTP request, holds no key on your behalf, and never sees a payment. The relay, the store and the gas station above contain no payment code at all.

Which chains and tokens?

The live node settles in USDC on Base mainnet and Solana mainnet. You choose the token and chain in the settlement block of your config. On EVM the channel contract is x402's x402BatchSettlement; on Solana it is the Solana Foundation's payment-channels program. Base Sepolia and Solana devnet are the devnets.

What is the smallest payment?

One base unit of the token. In USDC that is a millionth of a dollar. A voucher is a signature, so a tenth of a cent is a real price with no gas attached to it.

Does a caller need an account or an API key?

No. A caller needs a wallet with a deposit in the token the node prices in. It opens a channel once and attaches a voucher to each request. The node never learns who the caller is beyond the key that signs.

What happens to an unpaid request?

It is refused before it reaches your app, with an x402 402 Payment Required that states the exact price, token, chain and address. The caller pays and sends again. A refusal is a value in the client, not an exception. The 402 answers a well-formed packet that carries no voucher; a bare curl -X POST /ilp is not a packet and gets a 400. To read a price by hand, GET /ilp lists every route with its price.

When does the money land?

Claims are free and cumulative; the node lands the latest voucher on chain in batches, every ten minutes by default, and right away if the payer starts a withdrawal. One transaction settles everything since the last one.

What does TOON itself charge?

Nothing. The software is MIT licensed and there is no protocol fee. What a caller pays lands in the operator's channel, minus nothing. Gas for a batch settlement is paid by whoever lands it, once per batch, not per request.

Where do I find other nodes and apps?

There is no discovery layer by design (ADR 0046): a node answers for itself at GET /ilp and announces nothing. A peering is made from a URL (ADR 0058). The apps above are the ones the project runs; anyone can run the same images. The devnet reference lists three public nodes and six routes you can pay today without real money.

Put a price on it.

One Docker image, four lines of TOML, and your app is paid per request. The guide takes about ten minutes.
